# 승격 및 롤백 절차 — DRAFT / 운영 변경 없음

1. 동결 기준 커밋/원문 SHA/플러그인 release 및 OFFICIAL_V17 원본·이벤트 별도 digest를 저장한다.
   현재 ledgerSha는 현재 상태와 원본을 포함하나 events 전체를 포함하지 않는다.
2. 별도 DB·비밀정보 없는 CI에서 단위/통합/회귀/순서/공백/반대방향/원장 보존 시험을 통과시킨다.
3. 시간순 데이터셋과 feature known-at provenance를 잠근다. 2019~2026 데이터가 있다고 가정하지 않는다.
4. 실제 측정기간·비용/슬리피지·레버리지 아닌 노출정의·국면별 최소표본·허용낙폭·검정가족을
   사용자와 확정한 뒤 protocolHash를 고정한다. 지금 초안의 null을 임의로 채우지 않는다.
5. 기준선·후보·보류·역방향에 같은 기간·비용·중첩 정책을 적용한다.
   누출/실효 STOP 관리버전 문제/불명확한 OHLC 순서가 있으면 해당 결과를 미확인으로 격리한다.
   STOP/TP3율과 순손익, 기회상실, 잘못된 switching, drawdown을 함께 검증한다.
6. 홀드아웃을 열기 전에 모델·검정·가족 수를 잠근다. 열었다면 다시 선정용으로 사용하지 않는다.
   p값만 낮거나 승률만 좋아져서는 승격하지 않는다.
7. 연구 DB에서 shadow/paper를 운영하여 원장 쓰기 없이 결정 차이·지연·누락·용량을 관찰한다.
8. 검증 보고서와 실제 rollback 리허설을 완료한 뒤 사용자에게 구체적인 canary 범위·비용·중단 기준을 제시한다.
   현재 변경은 신규 매매 정책 승격 승인을 요청할 단계에 도달하지 않았다.
9. Render workspace는 연결에서 조회한 My Workspace (tea-d5nj03cmrvns73fp6520)의 사용자 선택이 먼저 필요하다.
   실제 serviceId, deployId, branch, live commit, 자동배포 설정을 조회하기 전 운영 push/trigger를 하지 않는다.
10. 자동배포 브랜치에 push하면 배포될 수 있으므로 승인된 단계 전에 canonical에 merge하지 않는다.
11. 카나리는 새 신호 정책에만 적용하고 기존 ID·원본·기발생 사건을 그대로 둔다.
12. 코드/정책/플러그인 불일치·원장 불일치·데이터 공백·CI 실패·허용손실 위반시 신규발행 승격을 중지한다.
    이전 검증 코드/정책/플러그인으로 되돌리되 DB backup 복원으로 새 사건을 지우지 않는다.
    실패 배포 기간에 발생한 사건과 rollback 자체를 추가 로그로 기록한다.
13. commit SHA·CI URL·Render deploy ID/live 상태·API policy SHA·플러그인 release·원장/이벤트 전후 hash를 함께 확인한다.
